1. SUMMARY OF CHANGES (MySQL -> PostgreSQL & Render Support)
================================================================================

The following updates were made across the project:

1. pom.xml
   - Replaced "mysql-connector-j" with the official "org.postgresql:postgresql" driver.

2. src/main/resources/application.properties
   - Added: "server.port=${PORT:8080}" (Render dynamically assigns $PORT; defaults to 8080 locally).
   - Changed datasource URL to: "${SPRING_DATASOURCE_URL:jdbc:postgresql://localhost:5432/luminavibe}"
   - Changed driver to: "org.postgresql.Driver"
   - Changed dialect to: "org.hibernate.dialect.PostgreSQLDialect"

3. src/main/java/com/luminavibe/entities/Like.java
   - Replaced MySQL-specific inline columnDefinition="ENUM('post', 'comment')" with
     standard JPA length=20 to ensure clean Hibernate DDL table creation in PostgreSQL.

4. docker-compose.yml
   - Replaced MySQL 8.0 with PostgreSQL 16 (postgres:16-alpine on port 5432).
   - Configured pg_isready healthcheck to guarantee safe startup order.

5. Dockerfile
   - Multi-stage build remains 100% compatible with Render Docker runtime!

3. HOW TO RUN LOCALLY WITH POSTGRESQL IN DOCKER
================================================================================

Open PowerShell in the project root (c:\Users\aksha\OneDrive\Desktop\LuminaVibe-Backend):

1. Start Docker Desktop first.

2. Build and start PostgreSQL + Spring Boot:
   docker compose up --build -d

3. Check container status:
   docker compose ps

4. Follow backend startup logs:
   docker compose logs -f backend

5. Access PostgreSQL CLI inside container:
   docker exec -it luminavibe-postgres psql -U postgres -d luminavibe
   (Type '\dt' to list tables, '\q' to exit)

6. Stop containers:
   docker compose down

4. STEP-BY-STEP GUIDE: DEPLOYING TO RENDER
================================================================================

Step 1: Push your code to GitHub
--------------------------------
In your project directory, commit all changes and push:
   git add .
   git commit -m "Migrate to PostgreSQL and prepare for Render Docker deployment"
   git push origin main


Step 2: Create a PostgreSQL Database on Render
----------------------------------------------
1. Go to your Render Dashboard (https://dashboard.render.com).
2. Click "New +" -> "PostgreSQL".
3. Fill in:
   - Name: luminavibe-db
   - Database: luminavibe
   - User: postgres (or default generated by Render)
   - Region: Select nearest to your users (e.g., Singapore, Frankfurt, Oregon)
   - Plan: Free
4. Click "Create Database".
5. Wait ~1 minute until status is "Available".
6. Copy the "Internal Database URL" (if hosting backend on Render) OR note:
   - Host
   - Database
   - User
   - Password
   - Port (typically 5432)


Step 3: Create the Web Service on Render
----------------------------------------
1. On the Render Dashboard, click "New +" -> "Web Service".
2. Connect your GitHub repository ("LuminaVibe-Backend").
3. Configure the service:
   - Name: luminavibe-backend
   - Region: Same region as your database!
   - Language / Runtime: Docker
   - Instance Type: Free
4. DO NOT change Docker Command or Docker Context unless needed (default is fine).


Step 4: Configure Environment Variables on Render
-------------------------------------------------
In the "Environment Variables" section of your Web Service, add:

Key: SPRING_DATASOURCE_URL
Value: jdbc:postgresql://<RENDER_DB_HOST>:5432/<RENDER_DB_NAME>?sslmode=require
(Note: Always prefix with "jdbc:postgresql://" and append "?sslmode=require")

Key: SPRING_DATASOURCE_USERNAME
Value: <RENDER_DB_USER>

Key: SPRING_DATASOURCE_PASSWORD
Value: <RENDER_DB_PASSWORD>

Key: SPRING_JPA_HIBERNATE_DDL_AUTO
Value: update

Key: SPRING_APP_JWT_SECRET
Value: jfdjfhjdhfjdhfjdhfdjhfjhgrjirutirirutirjifjirhitgthythyyuhtyfghhhjjjhtdgyfrthtyutyt

Key: SPRING_APP_JWT_EXPIRATION_MS
Value: 432000000


Step 5: Deploy & Monitor
------------------------
1. Click "Deploy Web Service".
2. Render will automatically:
   - Clone your repo.
   - Run the multi-stage Docker build.
   - Inject the dynamic $PORT.
   - Run your Spring Boot application connected to Render PostgreSQL.
3. Once finished, Render gives you a live public URL:
   https://luminavibe-backend.onrender.com

5. DAY-TO-DAY DOCKER & POSTGRESQL COMMANDS
================================================================================

1. REBUILD BACKEND LOCALLY:
   docker compose build backend
   docker compose up -d backend

2. VIEW DATABASE TABLES LOCALLY:
   docker exec -it luminavibe-postgres psql -U postgres -d luminavibe -c "\dt"

3. DUMP / BACKUP POSTGRESQL DATABASE:
   docker exec -t luminavibe-postgres pg_dump -U postgres luminavibe > backup.sql

4. RESTORE POSTGRESQL DATABASE:
   Get-Content backup.sql | docker exec -i luminavibe-postgres psql -U postgres -d luminavibe

5. RESET DATABASE VOLUME (Clears local test data):
   docker compose down -v

6. COMMON ISSUES & TROUBLESHOOTING
================================================================================

Issue A: Render database connection fails with "SSL off"
Solution: Append "?sslmode=require" to the JDBC URL:
  jdbc:postgresql://<host>:5432/<database>?sslmode=require

Issue B: Render says "Connection refused" or cannot resolve host
Solution: If both database and web service are on Render, use the "Internal Database URL"
  host (e.g., dpg-xxxxx-a), and ensure both services are in the SAME Render Region.

Issue C: Render Free Tier "Spin Down"
Render Free web services spin down after 15 minutes of inactivity. The first request
after spin down can take 30-50 seconds to wake up. This is normal on the Free tier.

Issue D: Uploaded media on Render
On Render's Free tier, the filesystem is ephemeral (resets on restart). For long-term
production uploads, consider using an S3 bucket or Cloudinary in the future.
