Here is a simple explanation of how registration and login work and interact:

Step 1: User Registration (Sign Up)
When a new user signs up on the frontend, they send their details to the backend.

Endpoint used: POST /users (handled by 

UserController.java
)
How it works:
The frontend sends a JSON payload with username, email, and a plain text password.
The backend encrypts (hashes) the password using BCrypt so that raw passwords are never saved in plain text.
The user is saved to the database with the hashed password.
Step 2: User Login (Sign In)
Once the user is registered, they can log in.

Endpoint used: POST /auth/login (handled by 

AuthController.java
)
How it works:
The frontend sends a JSON body containing email and password (

LoginRequest
).
The backend queries the database for a user with that email.
The security manager compares the raw login password with the hashed password stored in the database.
If they match:
The backend generates a secure, signed JWT (JSON Web Token).
The backend returns a 

LoginResponse
 containing the JWT token and the user's profile details.
If they do not match, it returns 401 Unauthorized (Bad credentials).
Step 3: Making Protected API Requests
After a successful login, how does the frontend stay logged in?

The frontend saves the received JWT token in storage (like localStorage).
For every subsequent request to a protected endpoint (like fetching posts or editing profile), the frontend attaches the token in the HTTP header:
http
Authorization: Bearer <your-jwt-token-here>
The backend's 

AuthTokenFilter
automatically intercepts the request, checks if the token is valid, and lets the request pass through if authenticated.
